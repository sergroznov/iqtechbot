# Бот-флаер для открытия точки СЦ

## Как это работает

**Клиент** (`/start`):
1. Бот проверяет подписку на канал. Нет подписки — кнопки «Перейти в канал» и «Я подписался».
2. Клиент нажимает кнопку «Отправить мой номер» (Telegram сам подтверждает, что номер принадлежит ему — чужой номер ввести нельзя).
3. Пишет марку и модель гаджета. Ник в Telegram бот берёт сам.
4. Выбирает услугу: **поклейка плёнки** или **чистка и чекап**.
5. Получает QR-флаер с кодом и сроком действия.

**Сотрудник**:
1. Сканирует QR клиента обычной камерой телефона (или камерой Telegram) → открывается бот с карточкой: услуга, клиент, телефон, устройство, статус, подписан ли ещё на канал.
2. Нажимает «✅ Погасить флаер». Клиенту приходит сообщение, что флаер использован.
3. Если QR показывает не сотрудник, а обычный клиент — бот просто покажет ему его собственный флаер. Погасить может только сотрудник.

**Защита от дублей**
- Один флаер на один Telegram-аккаунт **и** на один номер телефона (проверка в базе, уникальные ключи).
- Отписка и повторная подписка, повторный вход в бота, `/start` заново — ничего не дают: бот находит запись и показывает статус (активен / использован / истёк).
- Гашение атомарное: два сотрудника одновременно не смогут погасить один флаер дважды.
- Новый аккаунт с тем же номером телефона получить второй флаер не сможет.

**Панель сотрудника** — одно сообщение с кнопками (открывается по `/start` или `/menu`): поиск флаера по коду, статистика, последние погашения. Только для админов (ID из `ADMIN_IDS`): список сотрудников с добавлением (кнопка → отправить ID) и удалением, выгрузка CSV для Excel.

**Картинка в приветствии**: положите файл `assets/welcome.jpg` (или `welcome.png`) в репозиторий, ширина ~1280 px, до 5 МБ. Нет файла — приветствие уходит текстом.

## Шаг 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username (должен заканчиваться на `bot`).
2. Скопируйте токен — это `BOT_TOKEN`. Никому его не показывайте.
3. По желанию: `/setuserpic` (аватар), `/setdescription` (текст на стартовом экране бота).

## Шаг 2. Подключить канал

1. Откройте канал → Управление → Администраторы → **Добавить администратора** → найдите вашего бота. Достаточно минимальных прав — это нужно, чтобы бот мог проверять подписчиков.
2. `CHANNEL`:
   - публичный канал — `@username_канала`;
   - приватный — числовой ID вида `-100xxxxxxxxxx` (например, перешлите пост из канала боту @getidsbot) и ссылка-приглашение в `CHANNEL_URL`.

## Шаг 3. Узнать Telegram ID сотрудников

Каждый пишет боту [@userinfobot](https://t.me/userinfobot) и присылает вам число из `Id`. Ваш ID — в `ADMIN_IDS`. Остальных сотрудников потом добавляете командой `/addstaff ID` прямо в боте (каждый сотрудник должен хотя бы раз нажать `/start` у вашего бота).

## Шаг 4. Проверить локально (по желанию)

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env     # заполните значения
set -a && source .env && set +a
python bot.py
```
Напишите боту `/start` с другого аккаунта (не админского!) и пройдите весь путь клиента.
Проверять клиентскую часть с аккаунта админа/сотрудника нельзя: для них бот показывает панель сотрудника.

## Шаг 5. Где развернуть, чтобы работал 24/7

Бот работает через long polling: **домен, сертификаты и открытые порты не нужны** — достаточно любого сервера с выходом в интернет. Компьютер или ноутбук не подходит: выключили — бот лёг.

Самый простой вариант — **VPS** (виртуальный сервер, 1 CPU / 1 ГБ RAM хватает с запасом, обычно от нескольких сотен рублей в месяц). Берите Ubuntu 22.04/24.04. Подойдут российские хостеры (Timeweb, Selectel, Beget, REG.RU и др.) и зарубежные (Hetzner и др.). Если у выбранного хостера Telegram API вдруг работает нестабильно — просто возьмите сервер в другой стране; код менять не нужно.

### Вариант A (рекомендуемый): Docker

```bash
# на сервере, под root или через sudo
curl -fsSL https://get.docker.com | sh

# загрузите папку проекта на сервер (с вашего компьютера):
#   scp -r flyerbot root@IP_СЕРВЕРА:/opt/flyerbot
cd /opt/flyerbot
cp .env.example .env && nano .env      # заполнить токен, канал, ADMIN_IDS
docker compose up -d --build
docker compose logs -f                 # должно быть «Бот запущен: @...»
```
`restart: unless-stopped` — бот сам поднимется после сбоя и перезагрузки сервера. База лежит в `./data/bot.db`.

Обновление после правок: `docker compose up -d --build`.

### Вариант B: systemd без Docker

```bash
apt update && apt install -y python3-venv
useradd -r -m flyerbot
mkdir -p /opt/flyerbot && cd /opt/flyerbot     # скопируйте сюда файлы проекта
python3 -m venv venv && venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
chown -R flyerbot:flyerbot /opt/flyerbot
cp flyerbot.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now flyerbot
journalctl -u flyerbot -f                       # логи
```

## Шаг 6. Резервные копии

Вся база — файл `data/bot.db`. Раз в день копируйте его, например cron-задачей:
```bash
0 4 * * * cp /opt/flyerbot/data/bot.db /opt/flyerbot/data/bot-$(date +\%F).db
```
Также в любой момент можно выгрузить список командой `/export` в боте.

## Важно

- **Единственный экземпляр.** Запускайте только одну копию бота с одним токеном, иначе Telegram выдаст ошибку конфликта. Не запускайте тестовый локальный экземпляр, пока работает боевой.
- **Персональные данные.** Вы собираете телефоны и ники — это персональные данные. В боте есть строка о согласии на обработку, но по закону (152‑ФЗ) стоит также оформить политику обработки данных и, если нужно, уведомление в Роскомнадзор — уточните у юриста.
- **Срок флаера** задаётся `FLYER_DAYS`. Услуги меняются в словаре `SERVICES` в начале `bot.py` (например, можно добавить третью).
- **Если сотрудник погасил по ошибке**, правится вручную в базе: `sqlite3 data/bot.db "UPDATE flyers SET status='active', redeemed_at=NULL, redeemed_by=NULL WHERE code='КОД';"`
